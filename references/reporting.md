# Доказательства, отчёт и обращения

## Журнал доказательств

Оригинальные артефакты сохраняй в `evidence/`. Для анализа и обезличивания используй копии. Не перезаписывай ранний снимок новым. Не исполняй содержимое сохранённых файлов.

`evidence-index.csv` содержит:

```text
evidence_id,artifact_path,source,observed_at_utc,source_event_time,observation,limitations
```

- `artifact_path` — относительный путь в папке кейса.
- `source` — адрес первичного публичного источника либо описание предоставленного пользователем материала. Секретные и персонализированные ссылки остаются в закрытой локальной части.
- `observed_at_utc` — фактическое время получения, ISO 8601 с `Z`.
- `source_event_time` — время исходного события, если оно дано источником; неизвестное оставляй пустым. Не заменяй его временем скачивания.
- `observation` — что непосредственно видно; `limitations` — чего запись не устанавливает.

SHA-256 и размер файлов находятся в отдельном манифесте. `mtime_utc` в манифесте — метка файловой системы, не удостоверенное время события. Если ссылки/reparse points пропущены, укажи неполноту; не представляй такой манифест как покрывающий всё содержимое.

## Индикаторы

Минимальная таблица `ioc.csv`:

```text
type,value,role,status,observed_at_utc,source,evidence_ids,notes
```

`type`: domain, url, ip, file_sha256. `role`: например, страница-приманка, наблюдаемый адрес запроса, адрес размещения. Статус пиши словами: «подозрительный», «подтверждено данным отчётом», «только совпадение инфраструктуры». Он должен быть объяснён в `notes` и ссылкой на доказательство.

Домены официального бренда, общие CDN и публичные библиотеки перечисляй в контексте, если это нужно для разбора; не включай их в список для блокировки без отдельного подтверждения. Наблюдавшийся IP общего размещения сопровождай ограничением: запись не является рекомендацией блокировать весь адрес.

Не выдавай индикаторы в количестве, которого источник не обеспечивает. Подсчёт найденных доменов — размер имеющейся выборки. Отсутствие антивирусных обнаружений не удостоверяет безопасность.

## Итоговый отчёт

Используй [../assets/report-template.md](../assets/report-template.md). Заполняй только подтверждённые сведения; неподтверждённое поле заменяй на «не установлено». Каждый значимый вывод связывай с ID доказательства и источником. Не добавляй домыслы о группе, её составе, стране и мотивах.

Полный локальный отчёт может содержать предоставленные материалы потерпевшего, когда они нужны задаче. Для передачи готовь отдельную обезличенную копию. Скрывай личные адреса, телефоны, почту, номера документов/счетов, параметры URL, cookies, секреты и локальные пути с именами пользователей. Проверь также подписи и метаданные вложений.

## Получатели обращений

| Получатель | Основание для обращения |
|---|---|
| Оператор сети/хостинга | Подтверждённая связь страницы с ресурсом в указанное время |
| Регистратор | Подтверждённый домен и его регистрационные сведения |
| DNS/CDN-провайдер | Его установленная роль в обслуживании домена |
| Имитируемый бренд | Сохранённые признаки имитации его сервиса |
| Антифишинговый сервис/CERT | Его действующая официальная процедура приёма |

Сначала сохрани доказательства. Контакты найди в текущем официальном источнике. Записывай роль, адрес/форму, дату проверки и предусмотренные процедурой требования. Не обещай срок реакции или отключение ресурса.

Достаточность доказательств определяется конкретной процедурой. Сохранённый отчёт, снимок и технические сведения не требуют создания POST-пробы к API. Не придумывай правовые основания и не вставляй статьи законодательства без отдельной проверки их актуальности и применимости.

## Черновик обращения

Подставь только установленные сведения. Для иностранного получателя переведи на английский, сохранив смысл. Контакты заявителя заполняет пользователь.

```text
Получатель: [проверенный официальный адрес или форма]
Тема: Просьба проверить подозрительную страницу — [домен]

Здравствуйте.

Прошу проверить страницу. В сохранённых материалах наблюдается
[конкретные признаки, например запрос определённых категорий данных].
Если имитация бренда подтверждена: [описание и доказательство].

Домен: [домен]
Адрес страницы: [обезличенный URL с нужным для проверки путём]
Время наблюдения UTC: [время]
Связь с вашей инфраструктурой: [запись DNS/RDAP или другой источник]

Подтверждённые наблюдения:
[краткие факты с идентификаторами доказательств]

Материалы для проверки:
[обезличенные вложения или разрешённые ссылки на существующие отчёты]

Прошу рассмотреть обращение по вашей процедуре и сообщить его номер
или результат проверки.

Контакт заявителя: [пользователь заполняет сам]
```

Черновик не означает отправку. По прямому поручению пользователя отправляй только согласованный объём и сохраняй полученную квитанцию/номер. В журнале различай «подготовлено», «отправлено», «получен ответ». Если отправка недоступна, отдай пользователю готовые материалы.

RIPE NCC помогает с корректностью abuse-контактов, но не заменяет оператора при обработке инцидента. ICANN Contractual Compliance рассматривает вопросы договорного исполнения в своей сфере, а не любое мошенничество. Для эскалации сначала проверь подходящую текущую процедуру: [официальные источники](sources.md).
